# Domain 文档

工程技能在探索代码库时应如何消费本仓库的领域文档。

## 动手探索之前先读

- 仓库根目录的 **`CONTEXT.md`**，或
- 若根目录有 **`CONTEXT-MAP.md`**：它指向各上下文的 `CONTEXT.md`，只读与当前主题相关的那些。
- **`docs/adr/`**：阅读与即将动手的区域相关的 ADR。多上下文仓库还要看 `src/<context>/docs/adr/`。

若这些文件不存在，**静默继续**。不要强调缺失，也不要一上来建议创建。`/domain-modeling`（经 `/grill-with-docs` 与 `/improve-codebase-architecture`）只在术语或决策真正敲定后才惰性创建。

本仓库是**单上下文**：根目录一份 `CONTEXT.md` 加 `docs/adr/`。文档正文用中文，领域词用 `CONTEXT.md` 中的英文词。

## 使用词汇表里的词

工单标题、重构提议、假说、测试名里出现领域概念时，必须用 `CONTEXT.md` 定义的词，不要滑向词汇表明确 Avoid 的同义词。

若需要的概念还不在词汇表里：要么你在发明项目不用的语言（应改口），要么是真实缺口（留给 `/domain-modeling`）。

## 标出与 ADR 的冲突

输出若与已有 ADR 矛盾，必须显式写出，而不是悄悄覆盖：

> _与 ADR-0007 矛盾，但值得重开，因为…_
